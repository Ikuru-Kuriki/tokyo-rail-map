# 地域を追加する（例: 関西版）

首都圏版は、多くのやり取りを経て今の形になった。新しい地域では、そのやり取りを繰り返さないこと。この手順書に書いた仕様は、確認せずに満たす。ユーザーへの質問は「最初に確認すること」だけにし、残りは既定値で最後まで進める。

## ゴール

- 同じアプリに地域の切り替えを付ける（例: 首都圏 / 関西）。
  - ヘッダーのタイトルの横で選ぶ。URL のハッシュ（`#kansai`）でも選べる。
  - 選んだ地域はブラウザに保存する（try/catch で包む）。
- 時刻表のオープンデータが無い地域（関西など）では、終電とシミュレーションのタブを出さず、「経路」だけにする。
- 首都圏版の見た目・動作・データは変えない。

## 最初に確認すること（1 回だけ・まとめて聞く）

- 対象の範囲。関西の既定は、大阪・京都・神戸・奈良・和歌山・滋賀の JR 西日本、私鉄（阪急・阪神・京阪・近鉄・南海・山陽・神戸電鉄・能勢・北大阪急行など）、Osaka Metro、京都市営地下鉄、神戸市営地下鉄、モノレールなど。新幹線は除く。
- ほかに迷うことがあっても、既定値で進めて最後に報告する。

## データ

- 第一候補は、国土数値情報「鉄道（N02）」の GeoJSON。路線の形、駅、事業者名、路線名がそろっている。出典は「国土数値情報（鉄道データ）」と書く。
- 予備は OpenStreetMap の Overpass（`route=train|subway|light_rail|monorail` のリレーションと、駅の node）。出典は「© OpenStreetMap contributors (ODbL)」と書く。
- 駅ナンバリングは piuccio/open-data-jp-railway-stations の `stations.json`（`scripts/build-data.ts` の `NUMBERING_URL`）から、駅名と路線で合わせて入れる。
  - 合わない駅は、`src/domain/numbering.ts` の表で補う。
  - 関西の主要な記号の例: JR 西日本の A・JR・H、Osaka Metro の M・Y・T・C・S・K、阪急の HK、阪神の HS、京阪の KH、近鉄、南海の NK など。
- ダウンロードが通信制限で止まったら、`read_documentation`（topic: environment.network）を読む。そのうえで、ユーザーに許可するドメインと設定の場所を伝え、待つ。通信制限を迂回しない。
- 取得した元データは `.cache/`（git に入れない）に置く。
- 生成するスクリプトは `scripts/build-data-<id>.ts`、生成物は `src/data/regions/<id>/network.json` にする（生成物もコミットする）。
  - 型は `src/domain/types.ts` の `Network`（railways / stations / places / transfers）に合わせる。
  - 路線ごとの駅は、走行順に並べる。環状線（大阪環状線）は、先頭の駅を末尾にも入れる。
  - 同じ名前の駅（大阪 / 梅田は別の名前なので別の駅）は Place にまとめる。
    - 構内乗換は transfers の同じ内側の配列に入れる。
    - 徒歩連絡は別の配列に入れる。例: 梅田 ↔ 大阪 ↔ 東梅田 ↔ 西梅田 ↔ 北新地、難波 ↔ 大阪難波 ↔ JR難波、三宮 ↔ 三ノ宮。
  - 路線の色は各社の公式の色の表を作る（例: 大阪環状線 #F15A22、御堂筋線 #E5171F）。
  - 地下の深さは、`src/domain/depth.ts` に地域の表（路線の既定値と、深い駅の個別値）を足す。
  - 英語名（ローマ字）は必ず入れる。仮名で検索するときに使う。
- 駅数の目安は数百〜1000 程度。

## コードの地域対応

- `src/data/index.ts`: 地域ごとに network・graph・各 Map を作る。今の `network` などの名前は、首都圏の既定として残す。
  - 地域を切り替えたら作り直す必要があるので、`getRegion(id)` で返すか、React の context で配る。
  - 切り替えるたびに全部読み込まないよう、新しい地域の JSON は dynamic import にする。
- 地域ごとの設定 `src/data/regions.ts`（id、表示名、初期カメラ、地面と方眼の範囲、時刻表の有無、出典の文言）を作る。
  - 今コードに直接書いている値は、ここへ移す:
    - `GRID_BOUNDS`（`src/map/style.ts`）
    - `INITIAL_VIEW`（`src/map/RailMap.tsx`）
    - タイトル「首都圏 路線図」と出典（`src/App.tsx`）
- localStorage のキー（`src/data/history.ts` の履歴）は、地域ごとに分ける。
  - 首都圏は今のキーのまま使い、すでに保存された履歴を消さない。
- 地域を切り替えたら、入力中の駅・強調中の路線・経路をリセットする。
- `npm run data` のスクリプト名は首都圏のまま残し、`npm run data:kansai` を足す。

## 引き継ぐ仕様（すべて満たす）

**見た目**
- 方眼紙を斜め上から見下ろした 3D 風の地図にする。背景は `#f3f1ec`、白い角丸の駅名カードに柔らかい影を付ける。
- 地下の路線は深さを強調して描く。地下の駅からは縦線を引く。線の影は付けない。

**路線**
- 路線は複数強調できる。強調した路線は色を残し、ほかの路線はグレーにする。
- 強調した路線は、真横に近い角度から見る。
- 強調した路線の端に、路線記号（JK など）を出す。

**駅**
- 駅ナンバリングを出す。対象は、駅名ラベル・経路の結果・駅の候補で、強調した路線と経路で使う路線の分。
- 同じ名前で少しずつ位置が違う駅は、1 つの乗換駅として描く。
- 駅名ラベル・駅の点をクリックすると駅を選ぶ。
  - 出発と到着を入れた後に別の駅を選ぶと、到着を入れ替える。

**入力**
- 駅名の入力欄では、空のまま選ぶと最近使った駅（最大 8 件）を出す。
- ひらがな・カタカナでも探せる（`src/domain/search.ts` の仮名→ローマ字）。
- 変換中の Enter は、変換が確定してから候補を選ぶ。
- 候補を選ばずに入力欄から離れたら、先頭の候補を入れる。

**スマホ（768px 未満）**
- 検索と結果は、下から出るシート（小・中・大）に入れる。経路が出たら小さくする。
- 右上の「駅名」ボタンで、標準・主要駅・なし を切り替える。ラベルは小さめにする。
- 線をタップしたら、近くの駅を優先して選ぶ。駅が無ければ、路線名と「強調する」のカードを出す。
- 2 本指の回転・傾きを使えるようにする。右下に、拡大・縮小、真上 / 3D、北を上に戻すボタンを置く。

**PC**
- 検索パネルは左上に置き、「閉じる / 開く」で畳める。
- ホバーで、自前のツールチップと薄い強調を出す。

**全体**
- UI の文言はすべて日本語にする。

## 確認

- `npm run typecheck && npm test && npm run build` を通す。
- 新しい地域のデータのテストを書く:
  - 主要駅の間の経路が見つかる（梅田→京都、難波→三宮、天王寺→京橋、京都→奈良）。
  - 仮名で検索できる（うめだ→梅田、さんのみや→三宮）。
  - 主要駅に駅ナンバリングが入っている。
  - 路線の駅の並びで、隣の駅との距離が極端に離れていない（並び順の誤りを見つけるため）。
- Playwright で撮って、目で確かめる。
  - Chromium は `/opt/pw-browsers` にある。起動引数に `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` を付ける。`playwright install` はしない。
  - PC（1280×800）とスマホ（`devices['iPhone 13']`）で撮る。
  - 両方の地域で、初期表示、経路を出した状態、路線の強調を撮る。
  - 首都圏の見た目が変わっていないことも確かめる。

## 出し方

- ブランチ → PR → main にマージする。main に直接 push しない。
  - コミットの末尾と PR 本文の末尾には、セッションの指示にある署名行を付ける。
- 公開ページは、https://claude.ai/artifact/Gm65iS9oWhbZhApfeK8MxB を同じ URL のまま更新する。
  - `npm run build` の dist を scratchpad の `publish/` に置く。`index.html` は title・meta・link・script・`<div id="root">` だけの断片にする。
  - 先に Artifact の `list`（scope: files）で、公開中のファイルを確認する。
  - 新しいアセットと地域のデータを `files` で送る。名前が変わった古いアセットは `null` にする。
  - 時刻表（`timetable/`）は変わっていなければ送らない。
- README（機能の一覧・地域・出典）と CLAUDE.md（コマンド・構成）を更新する。

## 落とし穴（首都圏版で踏んだもの）

- 直通運転で路線が変わるところでは、区間が描かれずに抜けやすい（`src/domain/journeyRoute.ts` の junction の処理）。
- deck.gl の `getTooltip` は消えなかったり HTML の下に隠れたりする。ツールチップは `onHover` で自前に描く。
- iPhone では、16px 未満の入力欄をタップすると画面が拡大される（`src/index.css` で対策済み）。
- リポジトリに prettier の設定ファイルは無い。整形するときは `npx prettier --single-quote --print-width 120` を使う。既定の 80 桁のまま流すと、無関係の行まで崩れる。
- Python でファイルの一部を置き換えるときは、元の文字列が見つかることを `assert` で確かめる。
- 1 つの地域の駅数が多すぎると、ラベルの配置と描画が重くなる。主要でない支線は外してよい（外したものは報告する）。
